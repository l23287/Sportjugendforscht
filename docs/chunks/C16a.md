# C16a – Fix: „Failed to resolve import "jspdf"“ nach `git pull`

**Phase:** Flowstate D · **Branch:** `phase-1` · **Datum:** 22.11.2026 · **Status:** ✅ umgesetzt

## Problem

Nach dem Holen von C16 zeigte der lokale Dev-Server (Windows, VS Code) beim Öffnen der App:

```
[plugin:vite:import-analysis] Failed to resolve import "jspdf" from "src/lib/planPdf.ts". Does the file exist?
```

## Ursache

Der Code war korrekt. Mit C16 kam die Bibliothek **`jspdf`** neu hinzu, sie stand korrekt in `package.json` und
`package-lock.json`. Installierte Pakete liegen aber im Ordner `node_modules`, und der wird **nicht mit Git
übertragen**. Nach `git pull` fehlte `jspdf` deshalb lokal, solange niemand `npm install` ausgeführt hatte. Vite
prüft alle Importe schon beim Laden der Seite, auch den erst später genutzten dynamischen Import. Deshalb war gleich
die ganze Plan-Ansicht betroffen.

## Lösung

Neues Skript **`scripts/ensure-deps.mjs`**, das automatisch **vor** `npm run dev` und `npm run build` läuft
(`predev`/`prebuild` in `package.json`):

1. Es liest alle Pakete aus `package.json` (`dependencies` und `devDependencies`).
2. Es prüft, ob jedes Paket in `node_modules` vorhanden ist.
3. Fehlt eines, meldet es zum Beispiel „Fehlende Pakete: jspdf – führe „npm install“ aus …“ und installiert die
   Pakete selbst. Danach startet Vite normal.
4. Sind alle Pakete da, dauert die Prüfung nur Millisekunden, und es ändert sich nichts.

Das Skript läuft unter Windows, macOS und Linux. Damit tritt das Problem auch bei künftigen Chunks mit neuen Paketen
nicht mehr auf.

## Für den lokalen Rechner (einmalig, jetzt)

```bash
git pull
npm run dev
```

`npm run dev` installiert das fehlende `jspdf` jetzt automatisch. Alternativ geht wie bisher `npm install` von Hand.
